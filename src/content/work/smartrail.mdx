## Context

Zimbabwe's national railway needs a way to take fares. Riders mostly pay with mobile money, few
have bank cards, and connectivity and power both drop regularly.

## Decisions

Most modern fare systems ask a server whether you've paid. That fails the moment the network or
the grid does.

<Note kind="decision">
  **Card first.** A stored-value smart card holds its own balance, protected by cryptography, so a
  tap works with no network and no power. Mobile money and QR sit on top.
</Note>

One card handles both commuter tap-on/tap-off and reserved intercity seats.

## Build

<Plate label="Key hierarchy" caption="Gates hold the key that takes money. Only top-up devices hold the key that adds it. A stolen gate can’t create value.">
  <pre class="plate-pre">Master issuer key        (hardware security module)
        │ derived per card
        ▼
Per-card keys ── Debit        (gates)
              ├─ Credit/load  (top-up devices only)
              └─ Read/log     (inspectors)</pre>
  <p slot="text">A master key in a hardware security module derives keys for each card. Gates hold only the debit key, top-up devices the credit key, and inspectors can only read. A compromised gate can never add value.</p>
</Plate>

The whole tap happens between card and reader in under 300 ms. Transactions queue and sync when
the connection returns.
