## Context

Most Zimbabweans have never bought a share. Broker minimums, jargon and distrust left over from
the 2008 hyperinflation keep them out of the stock exchange.

## Problem

You learn to invest by deciding and being wrong, and most people can't afford to be wrong with
real money. The design problem: **keep the feeling of gain and loss, remove the risk.**

## Thinking

Paper trading for students and first-time investors, on cheap phones and metered data. So the
frontend stays light and installable.

<Note kind="decision">
  Game mechanics are there to turn "intimidating" into "progress", not to make trading addictive.
</Note>

## Design

Every trade earns experience (+10 for a buy, +15 for a sell, so taking profit is rewarded), with
levels and leaderboards so a class can compete. Prices are real, because a game with invented
numbers teaches nothing.

## Build

A Laravel application with virtual wallets and portfolios in MySQL. It worked. Then I read it the
way a busy server would.

## Iteration

<SignaturePlate slug="investment-gamified" />

Two requests arriving together could both read the same balance and both succeed, so a balance
could go negative. It's play money, but the same bug in a real wallet is a real loss.

I fixed it with **row locks**, and wrote seven tests that recreate the race directly. Then I added
an append-only audit table, and wrote down what I deliberately *wouldn't* build yet, and why.

<Note kind="rejected">
  Event sourcing. The audit table already records every change, and the extra machinery only pays
  off at a scale this doesn't have.
</Note>

## Result

A paper-trading platform whose trades stay correct under concurrent load, proven by tests.

<Note kind="open">Not yet tested with students in a classroom.</Note>

## Reflection

Every system I've built since asks one question first: *what if this runs twice at the same
time?* Knowing what not to build turned out to be a design skill too.
